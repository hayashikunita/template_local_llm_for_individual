# template_local_llm_for_individual

ローカルLLMアプリケーションを用途に合わせて作成するための、再利用可能なテンプレートリポジトリです。

特定業務の完成アプリやLLMのモデル本体ではなく、チャット・推論接続・保存などの共通構成を土台に、モデル・プロンプト・設定・文書を差し替えて使うことを目指します。

## 現在の状態

Python / FastAPI + React / TypeScriptによる、端末内限定の動作試作版があります。会話保存、ストリーミング、生成停止、認証付きAPIに加え、TXT・Markdownの登録と出典付きRAGを実装しています。要件定義書のPhase 1・Phase 2受入を完了した製品ではなく、公開・架空データによる検証専用です。

- [要件定義書](docs/requirements-definition.md)
- [試作の構成・API・制約](docs/prototype.md)

## できること

| 機能 | 内容 |
|---|---|
| 日本語の会話 | 導入済みのQwen3モデルで質問・相談に回答。同じ会話内の直前の発言を踏まえたやり取りを確認済み |
| 文章の作成・整理 | 入力した文章の要約、翻訳、言い換え、メールの下書きなどをモデルに依頼可能。正確性は人が確認 |
| 回答の逐次表示・停止 | 回答を生成途中から表示し、停止ボタンで中断 |
| 会話履歴 | 自動保存、再表示、タイトル検索、名前変更、削除、JSONエクスポート |
| モデル・生成設定 | 導入済みモデルの選択、温度と最大出力トークン数の調整 |
| ローカルAPI | APIキー認証付きで他のプログラムから利用。通常JSON応答とストリーミングに対応 |
| ナレッジ登録 | UTF-8のTXT・Markdownを画面から登録。原本保存、行番号付き内容抽出、全文検索索引の作成、一覧・原本取得・完全削除 |
| 文書検索（RAG） | 選択した文書の関連箇所を検索して実モデルへ渡し、文書名・行番号・原本SHA-256と参照本文を表示。出典を会話履歴にも保存 |

会話と推論はこのPC内で行いますが、モデル・依存パッケージの初回取得にはインターネットが必要です。業務利用の安全要件は未達のため、公開情報・架空データで試してください。

### 推奨する実装順

1. **配布と保全の土台:** 導入支援、バックアップ・復旧、監視・監査を整え、Phase 1の未達項目を減らす。
2. **文書利用の中核:** 実装済みのTXT・Markdownの登録・RAG・出典表示を検証し、PDF・XLSXへ広げる。Wordは要件上の将来拡張として後から判断する。
3. **変更管理とAPI:** モデル・プロンプト・設定の版管理とロールバックを整え、同じ認可・検証処理を使う文書・RAG・会話管理APIを追加する。
4. **利用範囲の拡張:** 複数人・複数端末で使う必要が確定した場合に、アカウント・役割別権限・会話共有を追加する。
5. **任意機能の評価:** Web検索、一般的な画像・音声機能、会話をまたぐ記憶は、用途・通信方針・データ保持方針が決まった後に採否を判断する。

優先度は、現在の単一利用者・端末内限定という前提で、安全な検証版から文書検索を備えた業務利用版へ進める場合の目安です。用途が音声入力や画像PDFの処理を必須とする場合は、その関連機能を前倒しします。

### 現在の設計で対象外

PCの自動操作や、人の承認なしで送信・登録・削除・発注などを行う自動実行エージェントは対象外です。単に実装待ちの機能として扱いません。専門判断の自動確定、不特定多数への公開サービス、外部クラウドLLMへの自動切替も対象外です。

## 現在の制約・欠点

| 項目 | 利用時の注意 |
|---|---|
| 回答の正確性 | もっともらしい誤回答があり得ます。短い日本語会話は確認済みですが、専門用途・要約・翻訳などの網羅的な品質評価は未実施です。回答は人が確認してください |
| 応答速度・動作環境 | このPCではCPU推論で確認しています。速度はモデル・入力・PC負荷に依存し、長文性能や必要メモリの体系的な測定、他環境での動作保証はありません |
| 長い会話 | 要求は100,000バイト以下、履歴は40メッセージ・24,000文字以下です。モデル別の厳密な入力トークン数の事前判定は未実装で、文字数上限内でもモデルが全履歴を参照できる保証はありません |
| 同時実行・生成上限 | 同時生成は1件で、処理中の別要求は拒否します。生成は最大120秒、出力は最大50,000文字で、生成設定やモデル側の上限も適用されます |
| データ消失 | 会話削除は完全削除です。生成途中の本文は完了・取消・失敗時に保存するため、プロセスの強制終了では途中の本文を失う場合があります |
| API利用 | OpenAI完全互換ではありません。初回有効化・キー発行には画面操作が必要で、キーは1時間で失効し、再起動でも無効になります。外部連携APIの会話は自動保存されません |
| 受入・導入検証 | 全要件の受入試験と非開発者3名による導入試験は未実施です。自動テストの成功は、実モデルの品質や業務利用の安全性の保証ではありません |

安全面の未整備事項は[安全上の前提](#安全上の前提)を参照してください。

## 起動する

このワークスペースでは依存・画面・Ollama・日本語モデルを導入済みです。PC再起動後は、リポジトリ直下で**2つのPowerShell端末**を開きます。すでに起動中なら重ねて実行する必要はありません。

端末1: モデル実行用のOllamaを起動し、そのまま開いておきます。

```powershell
.\scripts\start-ollama.ps1
```

端末2: アプリを起動し、そのまま開いておきます。

```powershell
.\scripts\start.ps1
```

ブラウザーが認証付きで自動的に開きます。既定の接続先は `http://127.0.0.1:8765` です。使用中の場合は別のポートを選び、実際のURLを端末に表示します。停止は起動した端末で `Ctrl+C`。通常起動にNode.jsやフロントエンド開発サーバーは不要です。

PowerShellの実行ポリシーでスクリプトが拒否される場合は、ポリシーを変更せず次の同等の起動コマンドを使えます。

```powershell
.\.venv\Scripts\python.exe -m backend
```

単にURLを開いただけでは新しいブラウザーは認証されません。自動で開いた画面を使ってください。画面セッションは12時間、起動リンクは5分・一回限りです。再起動すると既存の認証情報は失効します。

### 画面の使い方

1. 自動で開いた画面の「モデル一覧を更新」を押します。
2. モデル欄で `qwen3:4b-instruct-2507-q4_K_M` を選びます。「接続テスト」はLLMではない固定応答です。
3. 「新しい会話」を押し、下部の入力欄に日本語を入力します。
4. 送信ボタンまたは `Enter` で送ります。改行は `Shift+Enter` です。
5. 同じ会話で質問を続けると、それまでの履歴をモデルに渡します。話題を分けたいときは「新しい会話」を使います。

最初は「私の名前はハルです。明日は京都に行きます」と送り、続けて「私の名前と明日行く場所を教えて」と試せます。これは架空データを使った文脈確認の例です。

| 操作 | 方法 |
|---|---|
| 生成を途中で止める | 送信ボタンの位置に表示される停止ボタンを押す |
| 前の会話を開く | 左側の履歴から選ぶ。検索欄では会話タイトルを検索 |
| 会話名を変える | 会話上部の鉛筆アイコンから変更 |
| 会話を保存用に取り出す | 会話上部のダウンロードアイコンでJSON出力 |
| 会話を削除する | ごみ箱アイコンから確認後に削除。復元は不可 |
| 回答をコピーする | 回答下の「コピー」を押す |
| 生成設定を変える | 右上の設定アイコンから温度・最大出力トークン数を変更 |

設定に迷ったら既定値のままで構いません。温度は回答のばらつき、最大出力トークン数は回答の長さの上限に関係します。トークン数は文字数と同じではありません。

### 文書をナレッジとして使う

**対応形式はUTF-8の `.txt` と `.md` です。フォルダーに置くだけでは登録されません。** PDF・Excel・Word・画像・OCRは未対応です。拡張子だけ変えても対応形式にはなりません。

1. 左メニューの「ナレッジ」を開き、「文書を登録」でファイルを選びます。スマートフォン幅では左上のメニューから開きます。
2. 一覧に「検索可能」と表示されたことを確認し、検索対象の文書にチェックを付けます。登録時に内容を抽出し、検索索引まで自動作成します。
3. 必要なら検索語句を入力し、虫眼鏡ボタンで抽出本文と行番号を確認します。
4. 「選択文書で新しい会話」を押します。「文書検索」がONで、実モデルが選ばれていることを確認します。接続テストが選択されていた場合は、利用可能な最初のOllamaモデルを選びます。
5. 文書中の具体的な語句を含めて質問します。回答下の参照箇所を開くと、文書名、行番号、原本SHA-256、モデルへ渡した本文を確認できます。「原本」から登録時のファイル内容を取得できます。

試す文書は付属の [docs/knowledge-example.md](docs/knowledge-example.md) を使えます。登録後に「ミナト試験計画の受付コードと受付締切は？」と質問してください。公開・架空データのみを使用してください。

原本・抽出本文・検索索引は、既定で `%LOCALAPPDATA%\LocalLLMTemplate\knowledge.sqlite3` に保存します。`LOCAL_LLM_DATA_DIR` を指定した場合はその配下です。元ファイルは変更せず、フォルダーの監視や外部URLの取得も行いません。別の会話から同じ文書を選択できますが、モデル自体の追加学習ではありません。

| 項目 | 現在の仕様 |
|---|---|
| 容量・件数 | 1文書80,000バイト以下、100文書まで、同時に選択できる文書は20件まで。同内容の重複登録を拒否 |
| 検索方式 | SQLite FTS5の3文字単位の全文検索。2文字の検索語だけの場合は部分一致。意味検索ではないため言い換え・同義語や短すぎる語は見逃す場合あり |
| 検索と回答の範囲 | 検索確認は上位4箇所、回答に渡す本文は上位2箇所・各最大700文字。文書全体を読んだ回答や全文要約ではない |
| 質問・履歴 | RAGの質問は500文字以下、会話履歴を含む入力は合計2,000文字以下。厳密なモデル別トークン予算管理は未実装 |
| 根拠不足 | 一致箇所がなければLLMを呼ばず、その旨を表示。一致しても十分な根拠とは限らず、引用と回答の整合性は人が確認 |
| 履歴を開く・再読込 | 保存済みの回答・参照箇所を再表示。検索モードはOFFになるので、続きを文書検索で回答させる場合は対象文書を選び、ONにする |
| 削除・更新 | 削除は原本・抽出本文・索引をまとめて除去。生成中は削除不可。更新は旧文書を削除して再登録する方式で、原子的な版切替や復元は未対応 |
| 削除後の会話 | 過去の回答・参照本文は会話履歴とエクスポートに残り、削除後も会話文脈に含まれる場合あり。原本リンクは無効化される。全コピーの削除や安全な消去を保証しない |
| APIと権限 | 文書機能は認証済み画面専用。外部連携APIには未公開。複数ユーザー間の認可は未実装 |

2026-09-14に、導入済みQwenによる架空文書のRAG回答で、受付コード・期限・`[1]`の出典番号と原本ハッシュの保存を確認しました（約23秒）。有限の動作確認であり、回答品質やプロンプトインジェクションへの耐性を保証しません。

### 別の環境へ導入する

初回のソースからのセットアップにはPythonとnpmが必要です。Windows、Python 3.13、Node.js 22で動作を確認しています。Pythonとnpmが利用できる環境で実行してください。

```powershell
.\scripts\setup.ps1
.\scripts\start.ps1
```

セットアップはPyPI・npmから固定した依存を取得し、画面をビルドします。Node.jsはビルド用の固定版を一時的に利用し、システムのNode.jsを更新しません。LLMモデルは取得しません。まだ初心者向けのインストーラーや完全オフラインの配布パッケージはありません。

### 実際のLLMを使う

既定の「接続テスト」は画面・API確認用の固定応答で、LLMではありません。

1. 別途Ollamaを導入し、利用条件を確認したモデルを用意します。
2. Ollamaを `127.0.0.1:11434` で起動します。LANへ公開しないでください。
3. 画面のモデル一覧を更新し、登録済みモデルを選びます。

アプリはOllamaの一覧取得とチャットAPIにだけ接続し、モデルを自動ダウンロードしません。Ollama・各モデルの利用条件は別途確認が必要です。モデルがない場合にデモへ自動フォールバックすることもありません。

#### このワークスペースの導入済みモデル

2026-09-12にOllama 0.34.0と、日本語対応の `qwen3:4b-instruct-2507-q4_K_M`（4B、Q4_K_M、約2.5GB、Apache 2.0）を導入しました。アプリAPIとブラウザーで日本語の複数ターン会話・名前と予定の保持・履歴再表示を確認済みです。短い回答はこのPCで初回約12秒、続く回答は約3秒でした。応答時間・正確性は入力やPCの負荷で変わります。

日常の起動方法は[起動する](#起動する)、モデル選択は[画面の使い方](#画面の使い方)を参照してください。両サーバーの停止はそれぞれの端末で `Ctrl+C`。自動起動やシステムPATHの変更はしていません。

Ollama起動スクリプトはループバック待ち受けとクラウド無効を指定します。モデルは `%USERPROFILE%\.ollama\models` に保存され、Gitには含めません。別PCでは[公式Ollama 0.34.0の配布ページ](https://github.com/ollama/ollama/releases/tag/v0.34.0)から `ollama-windows-amd64.zip` を取得し、公式SHA-256を照合して `.tools/ollama/v0.34.0/` に展開するか、公式インストーラーで別途導入してください。このスクリプトはZIP版の配置を前提とします。

ZIP版を起動した後、別端末で同じモデルを取得するコマンドは次のとおりです。モデル取得時のみ外部通信と約2.5GBのダウンロードが発生します。接続不良で失敗した場合は、通信復旧後に同じコマンドで再開できます。

```powershell
& .\.tools\ollama\v0.34.0\ollama.exe pull qwen3:4b-instruct-2507-q4_K_M
```

### APIを使う

画面の「API連携」から有効化し、1時間有効のキーを発行します。キーはサーバーのメモリ上でハッシュ管理し、設定ファイルやログには保存しません。再発行は旧キーを、無効化はすべての連携キーを失効させます。以下はキーを画面から取得した後の例です。キーをソースや共有するコマンド履歴へ書き込まないでください。

```powershell
$secret = Read-Host 'API key' -AsSecureString
$credential = [pscredential]::new('local', $secret)
$headers = @{ Authorization = 'Bearer ' + $credential.GetNetworkCredential().Password }
$body = @{
	model = 'qwen3:4b-instruct-2507-q4_K_M'
	messages = @(@{ role = 'user'; content = '日本語で短く自己紹介してください。' })
	stream = $false
} | ConvertTo-Json -Depth 4
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/v1/chat' -Method Post -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
Remove-Variable secret, credential, headers
```

APIの会話内容はDBへ保存しません。`stream = $true` はSSE応答です。モデル一覧・キャンセル・仕様取得は[API一覧](docs/prototype.md#api)を参照してください。ポートが変わった場合は実際のURLへ変更します。

APIで会話を続ける場合は、過去の `user` と `assistant` のメッセージも `messages` に含め、最後を今回の `user` メッセージにしてください。画面と異なり、API側では履歴を自動追加しません。

### 保存先と用途の分離

既定の会話保存先はWindowsの `%LOCALAPPDATA%\LocalLLMTemplate` です。別用途では**初回起動前に**異なる保存先を指定してください。同じ保存先の多重起動は拒否します。保存先のアクセス権は利用者自身で確認してください。

```powershell
$env:LOCAL_LLM_DATA_DIR = Join-Path $PWD '.local-data\sample-a'
.\scripts\start.ps1
```

会話の削除は完全削除で、復元できません。必要な会話は先にJSONエクスポートしてください。

### 困ったとき

| 症状 | 確認すること |
|---|---|
| 固定応答しか返らない | モデル選択が「接続テスト」ではなくQwen3になっているか確認 |
| モデルが表示されない | Ollamaの起動を確認し、「モデル一覧を更新」。別PCではモデルの導入も必要 |
| ダウンロードが止まる | DNS・回線のエラーを確認。通信復旧後に `ollama pull` を再実行。アプリの再起動だけでは取得は完了しない |
| 認証が必要と表示される | アプリを停止・再起動し、自動で開くブラウザーを使う。起動リンクを共有しない |
| 回答が遅い・途中で終わる | 初回のモデル読み込みには時間が必要。短い入力で試し、出力上限を確認。生成は最大120秒 |
| 会話が長すぎると表示される | 必要な内容をエクスポートし、新しい会話を作成 |
| ポートや保存先が使用中 | 同じサーバーを重複起動していないか確認。既存の端末を使うか、そこで `Ctrl+C` 後に再起動 |

### テストする

```powershell
.\scripts\check.ps1
```

Pythonテスト、フロントエンドのlint・型検査・ビルド、ブラウザー操作テストを実行します。初回にテスト用ブラウザーがなければ `.\scripts\check.ps1 -InstallBrowser` を実行します（ダウンロードあり）。通常の自動テストはデモ／テスト用応答を使い、実モデルの回答品質を保証するものではありません。

### Gitへ含めないもの

[.gitignore](.gitignore) で、仮想環境、Node.js依存、ビルド、テスト結果、`.tools/`、`.local-data/`、SQLite、環境設定の秘密情報、モデル重みを除外します。リポジトリ内へ会話JSONを保存する場合は `exports/` を使ってください。任意の場所に置いたJSONや文書がすべて除外されるわけではありません。

秘密情報を含まない設定例の `.env.example` / `.env.sample` / `.env.template` と、依存の固定ファイルは管理対象です。すでにGitで追跡中のファイルには除外設定が効かないため、コミット前に差分を確認してください。モデル・ユーザーデータをテンプレートへ同梱しないでください。

## 提供する構成

以下は目標とする構成です。実装済み範囲は[試作の状態](docs/prototype.md)で管理します。

| 構成 | 内容 | 利用条件 |
|---|---|---|
| 最小チャット（Phase 1） | ローカル推論、チャット、会話保存、基本ログ、生成・モデル一覧・稼働確認API | 単一利用者・端末内限定。公開・架空データによる検証専用 |
| 文書検索（Phase 2） | PDF・XLSX・TXT・MarkdownのRAG、出典表示、認証・認可、監査、バックアップ、会話・RAG・文書管理API | 受入基準を満たし、承認後に業務利用 |

OCRは任意機能とし、最小チャットには導入を要求しません。外部クラウドLLMへの自動切替や、モデルの無断ダウンロードは行わない設計とします。

APIはPython側で提供し、通常のJSON応答、SSEによるストリーミング、生成キャンセルに対応します。他アプリ向け連携は既定で無効です。有効化と認証後は画面を閉じても利用できます。画面向けAPIと連携APIは認証を分けています。

## 想定する使い方

実装後は、次の流れで用途別の派生アプリを作成できるようにします。

1. このリポジトリを複製し、派生アプリ用のリポジトリを作成する。
2. アプリ名、利用モデル、プロンプト、保存先などを用途別に設定する。
3. ライセンスを確認したモデルと、必要な依存関係を手順に従って導入する。
4. 公開・架空データで最小チャットと通信制御を検証する。
5. 文書検索や業務利用が必要な場合は、Phase 2の機能と受入試験を追加し、承認を得る。

テンプレート本体には共通コードと配布用の例を置き、派生アプリの会話・文書・DB・インデックス・ログ・秘密情報は含めません。用途ごとの保存領域を分離し、共通コードへ個人の絶対パスを埋め込まない方針です。

## 安全上の前提

- 通常運用では外部サービスへ入力・文書・生成結果・埋め込みを送信せず、通信制御も検証します。
- Phase 1はループバックのみで待ち受け、実業務データや個人情報を投入しません。
- LLMの回答は人が確認し、業務処理を無承認で自動実行する機能は対象外とします。
- 派生アプリごとに環境と設定を検証します。テンプレートの試験結果だけで業務利用可能とは判断しません。

### 安全性・配布面の未整備事項

**業務利用の安全要件は未達です。機密情報・個人情報・実業務データは投入しないでください。**

- OS全体の外向き通信遮断は未実装です。ループバック接続・クラウド無効の設定や、ブラウザーテストで外部リクエストがないことは、OS全体の通信遮断の保証とは異なります。
- 保存領域のアクセス権（ACL）・暗号化状態の自動検証は未実装です。保存先がローカルであるだけで、他の利用者やプロセスから保護されるとは限りません。
- Ollama 0.34.0の実機ログでは、内部推論サーバーに「全Originを許可するCORS・APIキー未設定」の警告が出ています。影響範囲・対策の追加検証は未完了です。FastAPI側の認証・Origin制限だけで、推論ランタイム内部まで安全と判断しないでください。
- アプリ側の生成停止は確認していますが、Ollama側のGPU資源解放期限は実機で未検証です。
- 依存の既知脆弱性検査は実施していますが、将来の安全性や再配布条件の最終承認を意味しません。本体の配布用ライセンス選定、間接依存を含む採用・利用条件の記録、第三者表示の整備は未完了です。モデルのライセンスと本体の配布条件は別々に確認が必要です。

詳細な要件、導入フェーズ、受入基準、未決事項は[要件定義書](docs/requirements-definition.md)を参照してください。
